# Changelog

All notable changes to KDIGI CMS are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- **Agent skill `skills/kcms-frontend`** teaching AI coding agents to build a public website on the REST contract (anonymous reads, site filter, HTML fields, SEO and JSON-LD, menus, system pages, redirects, locales, revalidate webhook, routes matching `publicPathFor`), with references for Next.js, Astro, SvelteKit, Nuxt and React/Angular plus a done-checklist.
- **`kcms frontend context`** writes `KCMS.md` with one site's facts (tenant id, domain, locales, menus, `pageGroup`, counts, trimmed samples, routes, webhook URL) using anonymous REST only — no API key needed or sent.
- **`kcms setup <target> --with-skill [names]`** installs `kcms`, `kcms-frontend` or both (`--with-skill kcms,kcms-frontend`); a bare `--with-skill` still installs `kcms`. The npm package bundles every skill in `skills/`.
- **`/llms.txt` and `/llms-full.txt`** served from `public/` on the CMS host, generated by `pnpm generate:llms`; `pnpm test` fails when they are stale.
- Guide [docs/frontend-with-ai.md](docs/frontend-with-ai.md) ([Tiếng Việt](docs/frontend-with-ai.vi.md)).
- Demo seed: a `trang-chu` front page, one draft post, and `Sites.pageGroup` keys `FRONT_PAGE` / `ABOUT` / `CONTACT` (missing keys are backfilled on existing demo sites; keys you set are kept).

### Changed

- Docs: public hosts moved to `cms.kdigi.vn` / `docs.cms.kdigi.vn` / `app.cms.kdigi.vn`; demo login is now `demo@cms.kdigi.vn` (password unchanged).

## [1.2.0] - 2026-11-03

AI-native release. No database migrations; API-key sessions are restricted (see Changed).

### Added

- **AI-native: MCP server at `POST /api/mcp`.** 23 tools for AI agents (Claude Code, Codex, Cursor, VS Code, OMP, …) to search, write, schedule, publish, trash/restore, version, audit SEO and manage media and taxonomies, plus the resource `kcms://guide/content` and the prompts `write-post` / `refresh-seo`. Authentication is a user API key in `Authorization: Bearer …`; every call runs as that user with normal access rules, honours admin edit locks and requires `expectedUpdatedAt` for writes to existing documents. Enabled by default; `MCP_ENABLED=false` turns it off. See [docs/ai-integration.md](docs/ai-integration.md).
- **`kcms` CLI (`@kdigi/kcms-cli`, `packages/kcms-cli`):** Markdown-file round-trip for posts/pages, local image upload, `kcms setup <client>` that writes MCP config without embedding the key, and `kcms mcp` stdio bridge. The repository is now a pnpm workspace.
- **Agent skill `skills/kcms`** (Agent Skills format) teaching the editorial workflow; installed with `kcms setup … --with-skill`.

### Changed

- **Behaviour change — API-key sessions are restricted on all REST/GraphQL routes:** they can no longer create users or change email, password, API key, API-key switch, role or site membership, and can no longer permanently delete anything (content can still be moved to the trash). Browser sessions are unaffected. See [roles and permissions](docs/roles-and-permissions.md#api-keys-and-ai-agents).
- **`/api/media/from-url`:** downloads are pinned to the DNS answer that passed the SSRF check (no DNS-rebinding window) and every redirect hop is re-checked. Called with an API key it runs with the caller's access and accepts JPEG/PNG/WebP/GIF/AVIF only (type sniffed from the bytes).
- Author publish attempts now fail with HTTP `403` instead of a generic `500`.
- README, `package.json` description and the docs index now present KDIGI CMS as an AI-native CMS; `docs/architecture.md` documents the agent surface (`src/agent-api`, `src/mcp`, `packages/kcms-cli`, `skills/kcms`).

### Fixed

- Partial updates (REST/GraphQL `PATCH` that omit the field) no longer overwrite a filled `excerpt` with an auto-generated one, nor wipe `seo.breadcrumbs`.

## [1.1.0] - 2026-11-03

### Added

- **Public demo account protection (opt-in):** `DEMO_ACCOUNT_EMAILS` (comma list). Listed users cannot change their own email, password, API key or API-key switch and cannot delete themselves (`403`, bilingual vi/en message). Unset = no change in behaviour. See [configuration](docs/configuration.md#public-demo-accounts-optional) and [roles and permissions](docs/roles-and-permissions.md#demo-accounts).
- **`pnpm demo:reset`** (`src/seed/demo-reset.ts`): permanently deletes all content of the `demo` site only, re-seeds it with the demo seed and resets the accounts in `DEMO_ACCOUNT_EMAILS` (password from `DEMO_ACCOUNT_PASSWORD`, role `editor`, site `demo` only). Meant for a nightly scheduled task.
- **`REVALIDATE_SECRET`:** when set, the revalidate ping (job and the editor's manual button) sends the header `x-revalidate-secret`, so a frontend can verify the caller. Unset = unchanged unauthenticated ping.
- Both compose files forward `REVALIDATE_SECRET`, `DEMO_ACCOUNT_EMAILS` and `DEMO_ACCOUNT_PASSWORD`.
- README links to the project website, hosted docs and the live demo.

## [1.0.1] - 2026-11-03

### Fixed

- **WordPress migration, media phase:** `Media` gained the hidden `sourceMediaId` idempotency key (migration `20261103_052647_media_source_media_id`). Without it every media lookup failed, so featured images, sliders and inline images were not imported.
- **WordPress migration, re-runs:** media referenced only by URL (site logo, OG images) is keyed by a hash of its source URL and no longer re-uploaded on each run.
- **WordPress migration, source hosts with a port** (e.g. `127.0.0.1:8080`) are now matched when rewriting canonicals, menus and internal links.
- `--dry-run` on an empty database no longer reports missing inline-image targets as errors.

## [1.0.0] - 2026-11-03

First public release of KDIGI CMS (MIT), a headless multi-site CMS on Payload 3.90, Next.js 15 and PostgreSQL. It is extracted from a production multi-site system and generalised for agencies, bloggers, small businesses and people migrating off WordPress.

### Added

- **Multi-site:** one install serves many websites. Each `Sites` document holds branding, SEO defaults, contact/footer data, domain and optional storage credentials; content is scoped per site with explicit access predicates.
- **Roles:** `super-admin`, `admin`, `editor`, `author` with site assignment. Only a super-admin can change a user's `role` or site assignments; users editing their own account cannot escalate themselves.
- **Content model:** pages, posts, products (generic product/service pages), landings (block layouts), taxonomies, authors, menus (tree), FAQs, shortcodes, redirects, comments (with reCAPTCHA) and rating events. Content collections are versioned and localised (`vi` default, `en` with fallback).
- **Markdown-first editor** (Milkdown) with slash menu, media/link pickers, shortcodes, sanitised HTML output at the original REST field keys.
- **Media library** with folders, image editor, import from URL (SSRF-guarded), WebP conversion on upload for R2 sites. **Local-disk storage by default**; optional per-site Cloudflare R2 storage.
- **SEO subsystem:** JSON-LD graph generation, RankMath-style title/description placeholders, SEO audit, internal-link suggestions, optional AI SEO generation (DeepSeek API, enabled by `DEEPSEEK_API_KEY` and `DEEPSEEK_MODEL`).
- **Editorial tools:** content calendar / editorial dashboard, content trash and restore.
- **Frontend integration:** REST and GraphQL APIs, ISR revalidation job, frontend document URL resolver.
- **WordPress migration pipeline** (raw → staged → import) with runbook in [`docs/wordpress-migration/`](docs/wordpress-migration/README.md).
- **One-command local start** with Docker Compose (PostgreSQL + app) and a demo site with sample content.
- Documentation set under [`docs/`](docs/README.md), community files (Code of Conduct, Contributing, Security policy, issue/PR templates), CI workflow.

### Removed (relative to the private origin)

Domain-specific modules, optional CDN tooling, cloning pipelines and all site-specific one-off importers and fixtures from the private origin were not carried over to the open-source product.
